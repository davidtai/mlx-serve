DeepSeek-V4.1-Flash-1017 on mlx-serve: context sweep

Two Mac Studio M5 Ultra, 512 GB each. DeepSeek-V4.1-Flash-1017; pack DeepSeek-V4.1-Flash-1017-NVFP4-mlx-nvfp4 (the default NVFP4 pack); mlx-serve build a99fc4f6 for the release (final release bundle ds41lev-relfinalf-a99fc4f6, mlx-serve binary sha256 2eb2c922); the four stacks: mlx-serve 7343ce1e (bundle ds41lev-final1256-7343ce1e, mlx-serve sha256 1f8e6768311c).
Method: one fresh server per run; greedy and card (T 1.0, top-p 0.95), seeds 1234 and 4321; --ctx-size = N + 16,384; max_tokens 16,384; --warmup-full; 40 C cool gate; the code-ctx prompt family.
Every run (the release, the Nov 20 starting stack and the four stacks, 264 runs) stopped on its own at 509-880 output tokens. Prefill and decode tok/s from the server's own line; TTFT and wall time client side. 1K-64K and 512K on machine 1; 128K, 256K and 1M on machine 2 (machine 2 measures ~0.8% slower per verify round than machine 1 at equal text). Fans at max on both machines for every point (the release sweep: machine 2 from 16:17 UTC, machine 1 from 18:12 UTC; each set back to auto after its last window, at 18:13 and 18:53 UTC). DSpark on = the shipped drafter (block 5, 3 stages); the four stacks and the NVFP4 release all run DSpark on, as served. The four stacks: mlx-serve 7343ce1e (bundle ds41lev-final1256-7343ce1e, mlx-serve sha256 1f8e6768311c), the release a99fc4f6 plus four prompt-pass switches (PF_COMP_PASS, PF_IDX_PASS, PF_DOWN_BK32, PF_CED_COMP), the paired fp4 gate/up (MOE_PAIR_FP4), the prompt pass cap (PF_PASS_CEIL), the macOS warm plan, and --precision with the opt-in lossy int8 prompt path (PF_INT8=4), swept 2026-11-26 with the same prompts, seeds and method, fans at max; 1K-64K on machine 1 (16K first), 128K-1M on machine 2. The release's 512K point ran on machine 1, so the stacks' 512K points carry the ~0.8% machine-2 offset against it. Lossless: exact math or bounded reorders, no lossy quantization, with DSpark's default exact acceptance. Lossy, not lossless: MLX_SERVE_DSV41_PRECISION=lossy (--precision lossy) turns on int8 level 4 (wq_b, wo_b, the shared expert and wq_a+wkv on int8 w8a8) plus typical acceptance ε 0.09 / δ 0.3 (Medusa standard), card runs only; typical acceptance acts only on card runs; the greedy runs show int8 alone. Fastest = the higher mean greedy prefill over the sweep (each size the mean of its 2 seeds, then the mean over the sizes both stacks ran). Fastest lossless = MXFP4 lossless (mean greedy prefill 1K-1M: 4,816 tok/s vs NVFP4 lossless 4,777 tok/s, +0.8%). Fastest lossy = MXFP4 lossy (mean greedy prefill 1K-1M: 5,310 tok/s vs NVFP4 lossy 5,263 tok/s, +0.9%); per size, NVFP4 lossy prefills faster at 1M. The absolute charts show the NVFP4 release, the fastest lossless stack (MXFP4 lossless) and the fastest lossy stack (MXFP4 lossy), with the Nov 20 starting stack (before optimization) as a grey dashed reference line; the % charts show all four stacks and the starting stack against the release.
1M point: a 1,032,192-token prompt (1,048,576 - 16,384) built by ctx_long_build.py, the long fixture's recorded construction (the original generator is gone): it rebuilds the fixture's 256K and 1M cases byte for byte; at 512K it cuts 3 chars later than the fixture with the same 524,288 ids. The 512K point uses the fixture's case as is. Tokenizer sha256 c90dfa01.
NVFP4 lossless: mlx-serve 7343ce1e (bundle ds41lev-final1256-7343ce1e, mlx-serve sha256 1f8e6768311c); NVFP4 routed experts, lossless (exact math or bounded reorders, no lossy quantization) against each switch's =0 path on the NVFP4 pack (EXACT switches bit-identical; REORDER ones held to float64 or a stated bound, per the frozen build's README); its wikitext-2 PPL passed the lossless gate (2.9484 vs 2.9483 for the gate's reference arm), with DSpark's default exact acceptance.
NVFP4 lossy: mlx-serve 7343ce1e (bundle ds41lev-final1256-7343ce1e, mlx-serve sha256 1f8e6768311c); NVFP4 routed experts; not lossless: MLX_SERVE_DSV41_PRECISION=lossy (--precision lossy) turns on int8 level 4 (wq_b, wo_b, the shared expert and wq_a+wkv on int8 w8a8) plus typical acceptance ε 0.09 / δ 0.3 (Medusa standard), card runs only; typical acceptance acts only on card runs; the greedy runs show int8 alone.
MXFP4 lossless: mlx-serve 7343ce1e (bundle ds41lev-final1256-7343ce1e, mlx-serve sha256 1f8e6768311c) with MLX_SERVE_DSV41_MXFP4_VIEW=1 (experts_mxfp4), which serves the routed experts as MXFP4 (scales held as e8m0); lossless (exact math or bounded reorders, no lossy quantization) against the same =0 paths, with the NVFP4 pack's routed experts read as MXFP4 (MXFP4_VIEW: value-identical to NVIDIA's NVFP4 form for this checkpoint only, every scale a power of two); its wikitext-2 PPL passed the lossless gate (2.9484 vs 2.9483 for the gate's reference arm), with DSpark's default exact acceptance.
MXFP4 lossy: mlx-serve 7343ce1e (bundle ds41lev-final1256-7343ce1e, mlx-serve sha256 1f8e6768311c) with MLX_SERVE_DSV41_MXFP4_VIEW=1 (experts_mxfp4) (MXFP4 routed experts, e8m0 scales); not lossless: MLX_SERVE_DSV41_PRECISION=lossy (--precision lossy) turns on int8 level 4 (wq_b, wo_b, the shared expert and wq_a+wkv on int8 w8a8) plus typical acceptance ε 0.09 / δ 0.3 (Medusa standard), card runs only; typical acceptance acts only on card runs; the greedy runs show int8 alone.
Grey dashed: the Nov 20 starting stack, before optimization: bundle ds41nv (main 9e3311c2 plus the Engram MXFP4 path and residency; the bundle records no source commit; mlx-serve binary sha256 534d15b30033), the core deepseek_v41 runner with no plugin and no server envs, serving the separate MXFP4-experts pack (DeepSeek-V4.1-Flash-1017-NVFP4-mlx-mxfp4), DSpark on (block 5, 3 stages); swept 1K-1M on 2026-11-24 with the same prompts, seeds and method, fans at max; 1K-64K on machine 1, 128K-1M on machine 2.
